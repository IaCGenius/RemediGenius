# Your first useful investigation

Start with the private-preview bundle's `START-HERE.md` for the tested prebuilt Docker image. If you only have the source, run `docker compose up --build -d`; this rebuild downloads dependencies and is not the same frozen image. Open http://127.0.0.1:8765.

## About 15 minutes, no account or model key

1. Select **Try the sample workspace**. It creates synthetic before/after evidence; no AWS or model call occurs.
2. Under **Findings to investigate**, choose the SSH ingress finding and **Investigate**. Read the evidence, observation time, rule severity and coverage. The rule checks configuration, not actual network exploitability.
3. Choose **Prepare proposal**. It is a deterministic draft for review; nothing is executed and no model was called.
4. Open **Knowledge**. Enter a short note such as “The platform owner must review SSH access before any change.” Choose **Review this guidance**, inspect its wording/scope, then **Use this guidance**. Leave the default workspace scope for this sample. Reopen the investigation/proposal to see it applied without changing the scanner severity.
5. Use **Reassess a change** to compare the sample's earlier and later assessments. The sample can show that the rule no longer matches; this does not claim CE executed a fix. Imported or incomplete evidence cannot make the same trusted clearance claim.
6. Open **Connections → Use your agent with readable files**. Choose the assessment, **Export readable workspace**, then **Download investigation ZIP**. Extract it and read `START-HERE.md`. The skill and evidence are readable in an ordinary editor. If you choose to use Hermes or another agent, give it only this selected folder and ask it to separate source facts, deterministic checks, reviewed context and AI interpretation. The sample contains no real AWS data.

For a contextual variation, select existing guidance in Knowledge and narrow **Where it applies**. Missing context or conflicting guidance requires review; a variation does not suppress a scanner result. The [simple knowledge guide](KNOWLEDGE-SIMPLE.md) covers documents, AI-assisted drafting, edits and readable Markdown copies.

## Native Python instead of Docker

Requires Python 3.11+; Python 3.12 is the tested path. From an extracted source checkout:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install ".[aws,documents]"
.\.venv\Scripts\python -m rgce serve
```

Linux/macOS: use `.venv/bin/python`. Installation uses the configured package index. From the sharing bundle you may instead install its wheel with the same extras; commands are in `START-HERE.md`. There is no PyPI publication. MCP is optional and is not required for the sample or file-based agent workflow.

Native data defaults to `~/.rgce`. To isolate a trial, run `python -m rgce --home PATH_TO_NEW_WORKSPACE serve`. Docker uses its named volume. Stop writers before backing up local storage and copy the entire data directory, including document originals, not only SQLite. Never delete the Docker volume to stop compute. [Storage modes and recovery](DURABLE-WORKSPACE.md).

## Bring one real source

First follow [AWS onboarding](AWS-ONBOARDING.md) to establish the scoped read role. Choose one source, not the whole estate. In **Connections**, review the generated read plan and its access/cost limits. This review makes no AWS calls.

For a Docker or S3 console, the displayed command runs in a CE virtual environment on your workstation and writes `ce-evidence.json`. Activate that environment first, add your AWS `--profile` and required `--external-id`, and optionally use `--check` for one page/object. The command refuses to overwrite an existing output. Review the file, then choose **Import evidence** in the console. Imports have unverified coverage; no model submission happens automatically.

A native local-data console can instead generate a command writing to that same local workspace. Do not run multiple writers against an S3 prefix. Logs and S3 objects are context, not automatic configuration assessments.

For Security Hub or security-group findings use `collect-aws`; with a remote/Docker console add `--output selected-findings.json` and import the file. Inspector and GuardDuty are reused through existing Security Hub integrations, not direct adapters. Full command examples and scope limitations are in [source onboarding](WORKSPACE-ONBOARDING.md).

## Agent setup

Hermes remains an independent runtime. Use its native model/provider configuration; CE neither stores model keys nor implements a second provider client. Give your agent a selected investigation ZIP and the included skill. Exports are snapshots: regenerate after changing evidence or guidance. Do not give an investigation agent admin credentials to compensate for missing evidence.

Optional stdio MCP is supported with a native local-data CE installation and its `mcp` extra. Run `python -m rgce connect`, then merge the configuration into a dedicated compatible client profile. Container paths are not workstation paths; the Docker/S3 console directs users to file exports instead. A chat subscription does not automatically include API access or local MCP support.

## Finish and give feedback

Stop Docker with `docker compose down` from its Compose directory. This preserves the named volume. Start again with `docker compose up -d --pull never` when using the bundle's prebuilt runtime. Native Python stops with Ctrl+C.

Use the bundle's `FEEDBACK.md` or [feedback template](FEEDBACK.md). Send observations privately to the person who shared it. Include the step where you became confused, not your cloud exports or customer documents. Optional AWS resources must be stopped separately; S3/EBS retention can continue to incur charges.
