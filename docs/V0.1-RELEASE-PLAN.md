# CE release scope

AWS us-east-1, native Hermes, one ce-desk profile, self-hosted Docker or AWS Spot.
The current test model is DeepSeek v4.1 Flash. Bring your own permitted
model endpoint and key. See [validation](RELEASE-VALIDATION.md) for release evidence.

| Delivered capability | Accepted boundary |
|---|---|
| Bounded security investigation | Fixed stages; Hermes selects permitted evidence. Facts and scope must be traceable, wording may vary. |
| AWS evidence | Separate deterministic collector on the selected compute; original responses, deterministic projections and receipts in S3. |
| Daily checks | Collect and compare; no automatic model investigation or case creation. |
| Organizational knowledge | Operator imports files, selects collections, publishes/activates a view. |
| Remediation proposals | CLI, Terraform or CloudFormation; actual offline tools validate the draft. Operator executes changes. |
| Case tracking | Native local Kanban; explicit notes, waiting, verification and disposition. No AWS finding suppression. |
| Durable runtime | Sessions, workflows and Kanban on retained Docker volume/EBS. Evidence and private runtime recovery checkpoints in S3. |
| Usage control | Persistent action/loop limits and model output/time limits; no global token-cost ceiling. |

Release checks cover repeated real-model behavior, deterministic tests, Docker and
Spot operation, retained-state upgrades and clean source packaging. They do not
promise identical prose or universal correctness. Do not overwrite older release tags.
