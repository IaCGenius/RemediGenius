A SECOND BRAIN WITH RECEIPTS

Shared knowledge

Bring policies, architecture notes, ownership records and runbooks into a shared source library. Organize them by topic and scope. Turn sources into reusable, reviewed requirements and contextual variations with citations. Uploaded documents are sources, not automatically approved facts.

How to put knowledge to work

  1. Add policies, owner information and runbooks. Choose their topic and scope.
  2. Read the source, then create a reusable concept below. Give it a requirement key, scope, review date and source citation. A variation names the baseline version it changes.
  3. Review and publish the concept. Open Investigate to see applicable guidance, confirm missing application context, then prepare a proposal with a saved knowledge-use receipt.

What is used now: investigations resolve reusable concepts against resource context and include assessment-specific notes. Connected agents can retrieve the same knowledge through MCP. Uploading a document does not mean an agent has read or applied it.

Proposals: the console supplies a fixed review template and references approved context. It does not automatically rewrite the proposed steps from your documents.

Exceptions: an exception file or approved note records context only. Reusable knowledge variations are evaluated by exact scope, baseline version and review time. Risk-acceptance workflows remain separate and are not implemented. Keep your existing exception register authoritative and check it before acting.

New evidence: reusable concepts are selected again for each assessment; resource mappings and assessment-specific notes need renewed review. Conflicting or outdated guidance blocks a resolved recommendation.

What makes a result reliable?
Source evidence: what a source reported, at a stated time and scope. A provider finding can itself originate from AI.
Deterministic check: repeatable code applied to pinned inputs, with a rule version and code hash. Repeatability is not proof that the rule or input is complete.
Human-approved context: a reviewed, immutable statement. Context can be outdated; reassess it when evidence changes.
AI interpretation: a model's explanation or proposed action. It must cite evidence and remain separate from rule results. Cloud Hermes results are labeled AI interpretation and remain unreviewed until you assess their evidence.
